# Failure model

Each row states the observable signal, what keeps working, the finite limit before data loss, and how recovery happens. Limits are configuration defaults for the demo profile and must be checked against measured disk/RAM (see `docs/status.md`). A test ID refers to `tests/failure/` or `tests/integration/`. A row is only verified when status.md records a passing run.

## What this model does not claim

- It does not claim host-loss HA. All demo services share one host, one disk and one kernel.
- It does not claim zero loss across the link. UDP loss is reported and cannot be repaired without a return channel.
- It does not claim exactly-once external side effects. Sinks deduplicate by deterministic IDs, and the notifier deduplicates by stored processed update IDs.
